# Decision: Antigravity (agy) Transcript Location

**Date:** 2026-06-13  
**Status:** Resolved  

## Finding

Antigravity CLI (part of Google Gemini toolchain) stores conversation transcripts as **SQLite databases**, one file per session, at:

```
C:\Users\Zartc\.gemini\antigravity\conversations\<uuid>.db
```

There is also a parallel location for the IDE variant:
```
C:\Users\Zartc\.gemini\antigravity-ide\conversations\<uuid>.db
```

## Database Schema

Each `.db` file contains the following tables:

| Table | Key Columns | Notes |
|---|---|---|
| `trajectory_meta` | `trajectory_id`, `cascade_id`, `trajectory_type`, `source` | 1 row — the session identity |
| `steps` | `idx`, `step_type`, `status`, `step_payload` (BLOB), `render_info` (BLOB) | All events — the main stream |
| `gen_metadata` | `idx`, `data` (BLOB) | AI generation metadata |
| `executor_metadata` | `idx`, `data` (BLOB) | Tool execution metadata |
| `trajectory_metadata_blob` | `id`, `data` (BLOB) | Full session blob |

## Payload Format

All BLOB columns are **Protocol Buffer (protobuf)** encoded binary. No `.proto` schema files were found on disk — they are compiled into the Antigravity binary.

**What we can read without protobuf decoding:**
- `idx` (step index / ordering)
- `step_type` (numeric enum: 14=?, 98=?, 90=?)
- `status` (numeric: 3=completed?)
- `has_subtrajectory` (boolean)
- Unix timestamps are embedded at field offset `0x08` in the payload binary

**Step types observed in the wild:**
- `14` — appears first, likely "session start" or "user turn"
- `98` — appears after user input, likely "model response"
- `90` — appears interleaved, likely "tool use" or "shell execution"

## Collector Strategy

The Antigravity Collector will:
1. Watch `~/.gemini/antigravity/conversations/` using `chokidar` for new `.db` files
2. For each new `.db`, open a read-only SQLite connection
3. Poll the `steps` table for new rows (using `MAX(idx)` watermark)
4. Emit `AgentEvent` objects using the readable SQL columns
5. Include `step_type` and `status` in `event.metadata` for the frontend to display
6. **Full protobuf decoding** is a future enhancement — not in MVP

## Constraints

- **Read-only**: Never write to the `.db` files
- **Polling vs. WAL**: SQLite WAL mode may allow live tailing; test this in implementation
